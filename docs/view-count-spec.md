# 浏览量（view_count）对接说明 — 给 Android 客户端

更新时间：2026-09-12　后端：`worker/src/handlers/posts.ts`、`worker/src/db/queries.ts`

## 0. 一句话规则

**浏览量 = 看过这篇帖的人数（去重 UV），不是打开次数。**
由**服务端在「获取帖子详情」时自动记录**，客户端不需要、也不应该单独上报浏览。

## 1. 客户端需要做的事：几乎没有

- **展示**：列表 / 详情 / 用户主页 / 收藏等处，直接显示响应里的 `view_count`（整数）。
- **不要调用** `POST /api/stats/view/{postId}`：该接口**已删除**，调用会返回 404。
  - 已核对你们的仓库：`ApiService.recordView` 与 `ForumRepository.recordView` 有定义但**没有任何调用点**，建议删掉这两个方法以免后人误用。
- **登录态请求务必带** `Authorization: Bearer <access_token>`：服务端按「账号」去重；不带 token 会按「客户端出口 IP」记成游客浏览（登录用户的浏览会被算进游客口径）。

## 2. 服务端行为（去重规则）

| 访客 | 识别方式 | 去重粒度 |
|---|---|---|
| 登录用户 | access token 里的用户 id | 同一账号 **终身只算一次** / 帖 |
| 游客（无 token 或 token 失效） | 客户端出口 IP（服务端加盐哈希后存储，不存明文） | 同一 IP **终身只算一次** / 帖 |

- **记录时机**：`GET /api/posts/{id}` 被调用即记一次；服务端异步执行，不影响响应速度（失败只记服务端日志）。
- 响应里的 `view_count` 是**本次浏览之前**的值（本次是否 +1 取决于你是不是第一次看这篇帖）。
- 楼主自己看也算 1 次；匿名帖、付费帖同样计入（与是否解锁正文无关）。
- 数字**只增不减**，且增长缓慢——它表示「有多少人看过」，重复打开不会让它变大。

## 3. 接口

### 3.1 帖子详情（记录浏览 + 读数）

`GET /api/posts/{id}` — 公开接口；带 token 时按账号去重，不带则按 IP

```json
{
  "success": true,
  "data": {
    "id": 160,
    "title": "个人博客",
    "view_count": 42,
    "like_count": 2,
    "comment_count": 1
  }
}
```

### 3.2 列表（只读）

`GET /api/posts?page=&pageSize=`、板块列表、用户主页帖子、收藏列表等，列表项里带同一个字段：

```json
{ "id": 160, "title": "个人博客", "view_count": 43, "like_count": 2, "comment_count": 1 }
```

### 3.3 单帖浏览数（只读，可选）

`GET /api/stats/view/{postId}` — 公开，无需登录

```json
{ "success": true, "data": { "postId": 160, "viewCount": 43 } }
```

与详情里的 `view_count` 同源（同一物化值）。客户端一般用不到它。

### 3.4 已删除的接口

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /api/stats/view/{postId}` | **已删除**（404） | 浏览记录改由详情接口自动完成；旧接口用 IP 当身份、与详情路径口径冲突会重复计数，故移除 |

## 4. 客户端注意事项

1. **不要本地乐观 +1**：同一人重复浏览服务端不会 +1，本地 +1 会与服务端数值长期不一致。需要最新值就重新拉详情/列表。
2. **不需要任何访客标识参数**（设备 ID、指纹等）：去重完全由服务端按账号/token 或出口 IP 判定；客户端也不要自己做"我是否看过"的去重缓存。
3. 直接显示整数即可（全站量级不大，不需要 `1.2k` 之类的缩写）。
4. 游客的 IP 去重是服务端行为：同一 WiFi 下多人只算一次、手机切换网络会再算一次，属于预期，客户端无需处理。
5. 旧版本 App 即使仍在调用 `POST /stats/view` 也不会造成数据错误（浏览本来就由详情接口记录），只是那个请求会拿到 404，建议尽快清理。

## 5. 联调自测清单

1. 未登录打开一篇没看过的帖子 → 拿到 `view_count = N`；再打开一次 → 变成 N+1（因为你（该 IP）是第一次看）。
2. 同一账号反复打开同一篇 → 数字**不再增加**（除首次）。
3. 换个账号打开同一篇 → +1。
4. 同一 WiFi 下两台设备都未登录，打开同一篇 → 只算 1 次。
5. 登录态看过之后退出登录再看同一篇 → 会再 +1（账号口径与 IP 游客口径是两套身份，属预期）。
